## Czemu `remote_e_ok` bylo false przy `curl` 200

Adres byl dobry, port odpowiadal, a noga i tak meldowala sie jako martwa. Przyczyna nie
byla w adresie:

```
ContextLeg::remote_e(...)  ->  api_version: ChromaApi::V1   (na sztywno)
8001 /api/v2/heartbeat     ->  200
8001 /api/v1/heartbeat     ->  410 Gone
8000 /api/v1/heartbeat     ->  410 Gone
```

Wersja API byla **cecha tego, ktora to noga**, a nie tego, co stoi pod jej adresem.
`remote_e` mowilo V1, bo tak mowila Chroma na dysku E. Odkad ta noga wskazuje na wlasny,
wspolczesny serwer, V1 zwraca `410 Gone` - czyli "ta wersja juz nie istnieje". Noga pukala
do zamurowanych drzwi i uczciwie raportowala cisze.

Poprawka (`8395e40`): `ContextLeg::with_api` - dodane, zadnego istniejacego wywolania nie
zmienia. Serwer ustawia nodze zapasowej V2, a `DARKSTAR_CONTEXT_REMOTE_API=v1` zostaje na
wypadek powrotu tej nogi na starszy serwer. Wymagalo to przebudowy obrazu: adres idzie
przez compose, ale wersja API juz nie.

## PIERWSZA rzecz, ktora czeka: 8001 nie przezyje restartu

```
is-active  : active
is-enabled : disabled
```

Jednostka ma `WantedBy=multi-user.target`, ale nie zostala **wlaczona**. Po restarcie
maszyny wstanie tylko Chroma na 8000 i druga noga cicho zniknie - a `health` bedzie o tym
mowil prawde, ktorej nikt nie bedzie w tym momencie ogladal.

Wymaga roota, wiec nie zostalo zrobione:

```
sudo systemctl enable --now darkstar-chroma-e-copy.service
systemctl is-enabled darkstar-chroma-e-copy.service     # ma zwrocic: enabled
```

## DRUGA rzecz, ktora czeka: regula 41642 nadal nie jest w /etc

```
41642 w repo : 1
41642 w /etc : 0
```

Regula lezy w wersjonowanym `host-guard.nft` od kilku rund. **W tej sesji nie wykonano ani
`nft -f`, ani restartu `darkstar-firewall.service`** - i nie zostanie wykonane bez wyraznej
zgody. Dopoki `/etc` pokazuje `0`, wezly prywatnego mesh nie polacza sie bezposrednio.

Jedna linia dla operatora:

```
ssh owner@192.168.2.1 'sudo cp ~/polip-agi/deploy/firewall/host-guard.nft /etc/darkstar/host-guard.nft && sudo ~/polip-agi/deploy/firewall/darkstar-firewall-apply && grep -c "dport 41642" /etc/darkstar/host-guard.nft'
```

Ma zwrocic `loaded inet darkstar_host_guard` oraz `1`. Skrypt kasuje **wylacznie** tabele
`inet darkstar_host_guard`, waliduje `nft -c`, dopiero potem laduje - zaden inny lancuch
nie jest dotykany.
